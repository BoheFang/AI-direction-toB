背景介绍

在当今信息化时代，数据已成为企业发展的核心资产。根据IDC的统计和预测，全球数据量从2018年的33ZB增长至2025年的175ZB，其中非结构化数据占据了绝大部分。非结构化数据包括文本、图片、音频、视频等各种格式，其增长速度远超结构化数据。然而，企业在面对如此庞大的非结构化数据时，往往面临着诸多挑战。

首先，非结构化数据的存储和管理成本高昂。传统的存储设备难以满足大规模非结构化数据的需求，且数据备份和恢复过程繁琐，容易导致数据丢失。其次，非结构化数据的访问和控制困难。企业内部员工往往需要花费大量时间在多个系统中查找所需信息，且数据权限管理复杂，容易导致数据泄露。再者，非结构化数据的共享和协同低效。企业内部各部门之间往往存在信息孤岛，数据共享和协同困难，影响工作效率。

尽管非结构化数据蕴藏着巨大的价值，但目前其利用率仍处于较低水平。根据统计，55%-80%的业务数据处于沉睡状态，未被充分利用。

在此背景下，360AI企业知识库应运而生。其产品理念是：帮助企业实现海量非结构化数据的捕获、知识处理、知识库构建、场景应用、反馈闭环，沉淀企业的知识资产。

产品介绍

360AI企业知识库一款专为企业AI转型和高效落地智能体而打造的“企业级智能体应用知识中枢”产品，是企业AI核心基础设施。具备“AI知识库+企业级知识管理”双重特性，既能有效支撑智能体落地，又让企业知识管理“不混乱、更高效、更安全”。

产品采用先进的第三代AgenticRAG技术，具备企业级“文档+数据+互联网”搜索能力，可有效整合企业内外部多源异构多模态知识，构建“全域知识+知识技能MCP+知识增强Agent”三位一体知识协同体系。

产品架构

360AI企业知识库采用“分层解耦、模块化协同”架构设计，由模型管理、知识采集、知识处理、知识预览与AI副驾驶、问AI、智能体、知识生产、文件协作、知识管理、开放服务与安全治理等模块组成，覆盖知识“接入-处理-预览-问答-生产-协作-治理-开放”全流程。

V2.1进一步补齐了FAQ库、术语库、云盘关联导入、知识版本管理、问AI多模式、企业控制台精细化配置与安全中心等产品能力，使白皮书描述与当前功能清单保持一致。

核心能力摘录

全域知识采集：支持围绕文档库、FAQ库、术语库构建统一知识底座，并接入本地文件、云盘文件、网页内容及第三方平台内容。

多模态知识库：支持统一解析配置、知识片段管理、匹配测试、知识标签、文件预览与AI副驾驶等能力。

知识技能：平台内置混合检索、联网搜索、文件采集、会议纪要、录音转写、视频理解、网页生成、文件安全外发等多类知识MCP。

部署模式摘录

360AI企业知识库支持私有化部署、混合部署、SaaS订阅三种模式。私有化部署中，大模型服务器包含deepseek蒸馏版模型、qwen大模型、文档云大模型、版式分析模型、向量化模型、重排模型等服务。

AI知识库应用服务器基于k8s架构，数据库采用mysql，消息队列采用MQ主从服务，对象存储及ES构建分布式集群，网关层采用haproxy+keeplived保障主备节点的可用性。

SaaS订阅：针对一些中小规模的客户，无需提供任何本地资源，开通即用，快速交付。客户在https://www.fangcloud.com完成账号注册完成后，可根据自身情况自由选择合适的套餐。

初审结论

对照《产品白皮书撰写要求》和《XX产品白皮书模板_v1.0》的写作逻辑，逐章检查后，共发现 6 类全局共性问题和 30+ 处具体问题。当前稿件不建议直接对外发布。

一、最严重的 6 个全局共性问题

1. 技术黑话泛滥

AgenticRAG、MCP、RAG、向量化、多路召回、FG-CLIP、k8s 等表述密集，违反“产品白皮书不是技术白皮书”。

2. 违反“多定性少定量”

29种格式、98%+、效率提升70%/90%、PB级、SuperCLUE榜单第二等数字易被比对或随版本失真。

3. 章节结构缺失/错位

缺“产品目标”独立章节、缺“产品规格”章节；发展历程位置割裂；核心能力8项平级无层级。

4. 章节间缺乏呼应

背景只论证“数据多”，未论证“AI知识库是趋势”；痛点、产品、场景、优势之间映射不足。

5. 安全维度系统性缺位

360核心基因未作为主线出现，背景痛点集中在成本/效率，缺数据安全与合规风险。

6. 对外合规隐患

正文混入内部批注，暴露 fangcloud.com 外部品牌域名，案例含真实客户名和高比例承诺数据。

二、分章节具体问题与建议

1. 背景介绍

  • 趋势分析与产品赛道脱节：只引 IDC 数据增长，缺对 AI知识库/RAG 赛道地位的权威佐证。
  • 痛点未分条列出：建议改为项目符号列表，补足到 5-6 条，每条“加粗痛点 + 一句说明”。
  • 缺安全风险维度：建议增加“数据安全与合规风险”，并在引出产品时呼应 360 安全基因。
  • “55%-80%沉睡数据”无出处：补来源或改为定性表述。

2. 产品介绍与架构

  • 首句语病：“360AI企业知识库一款专为…产品”缺“是”字，首段第一句即硬伤。
  • 技术黑话堆砌：AgenticRAG、知识技能MCP、三位一体等需转译为业务语言。
  • 缺独立“产品目标”章节：建议新增小节，用“建立XX体系：解决XX问题”对应痛点。
  • 正文混入内部批注：删除“使白皮书描述与当前功能清单保持一致”。
  • 架构未逐模块描述：图后按流程补“职责 + 上下游关系”。

3. 核心能力

  • 开篇缺概括串联：建议按“知识进 → 用 → 管 → 安全”先给读者地图。
  • 8项能力平级无层级：差异化核心能力与支撑能力混同一级。
  • MCP逐条罗列像清单：建议按“能做什么”收敛为 3-5 类能力主题。
  • 定量堆砌：29种、22种、300MB、98%+、9级权限等应移入规格表。

4. 部署 / 规格 / 应用场景

  • 部署堆砌技术栈：k8s、mysql、MQ、ES、haproxy+keepalived 应改为“组件作用 + 客户保障”。
  • 完全缺失“产品规格”章节：建议用表格列资源需求、性能档位和适用场景。
  • 应用场景仅表格无正文：建议挑 2-3 个主打场景用“问题-方案-价值”展开。
  • 暴露外部域名 fangcloud.com：删除 URL，改为“联系360商务/参见附录”。

5. 产品优势 / 客户价值 / 案例实践

  • 优势6项与核心能力大量重复：建议重构为 3-4 条差异化优势。
  • 优势标题黑话化：“先进的多模态RAG解析技术”可改为“精准读懂复杂文档与图文内容”。
  • 客户价值“宏观/中观/微观”抽象：改为管理层、IT安全、一线使用者视角。
  • 案例实践含真实客户名和极端定量承诺：建议移出白皮书，另做受控客户案例集。

三、修改优先级建议

P0 立即修首句语病；删除内部批注、外部品牌域名、第三方模型名；案例去定量承诺并脱敏。
P1 全局质量全文去技术黑话；全文定量转定性。
P2 章节结构新增“产品目标”“产品规格”；核心能力做层级区分；背景补安全风险并改列表。
P3 呼应与差异化建立“趋势 → 痛点 → 产品 → 佐证”链；场景补正文；优势重构；补关键图表。
